# Contributing to ClearComm911

ClearComm911 is currently in the architecture and planning phase. Contribution guidelines will be published when the first implementation is ready for collaboration.

In the meantime, if you have domain knowledge in any of the following areas and want to be involved early, please open an issue:

- PSAP operations and dispatch workflows
- CJIS compliance and public safety data handling
- SIP/VoIP telephony and audio stream integration
- Speech-to-text in real-time or low-latency environments
- Machine translation in high-stakes or safety-critical contexts

All contributions will follow conventional commits and a PR-based workflow with branch protection on `main`.

## Developer Certificate of Origin (DCO)

To keep the provenance of every contribution clean — which matters for a project intended for
public safety use — we require a **DCO sign-off** on each commit. The DCO is a lightweight
statement (see [developercertificate.org](https://developercertificate.org/)) that you wrote
the contribution or otherwise have the right to submit it under the project's license.

Sign off by adding a `Signed-off-by` line to your commit message, which `git` adds automatically
with the `-s` flag:

```
git commit -s -m "your message"
```

This appends:

```
Signed-off-by: Your Name <your.email@example.com>
```

Commits without a valid sign-off may be asked to amend before merge.

> Note: a heavier-weight Contributor License Agreement (CLA) may be adopted later if the project's
> governance or stewardship requires it; the DCO is the current standard.
